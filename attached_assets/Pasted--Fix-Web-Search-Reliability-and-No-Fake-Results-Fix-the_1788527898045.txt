# Fix: Web Search Reliability and No-Fake-Results

Fix the web-search subsystem in `~/Personal-Linux-AI-Assistant`.

## Current bug

Lura's web search is unreliable.

Sometimes:

* A web-search request produces no response.
* Search results are incomplete.
* The model appears to answer without actually searching.
* The model may present information as current/live without verified search results.
* Search/tool failures are not always communicated correctly.
* The model may hallucinate or fabricate search results.

## CRITICAL REQUIREMENT

Lura must NEVER claim that it searched the web unless the web-search tool actually executed successfully and returned usable results.

If web search:

* fails
* times out
* is unavailable
* returns zero results
* returns malformed data
* encounters a network error

then Lura MUST NOT fabricate an answer or pretend that live information was retrieved.

It must return a clear structured error/status to the model.

---

# 1. Inspect before modifying

Trace the complete web-search pipeline:

USER REQUEST
→ ROUTER
→ SEARCH INTENT DETECTION
→ WEB SEARCH TOOL
→ HTTP REQUEST
→ SEARCH RESULT PARSER
→ STRUCTURED TOOL RESULT
→ MODEL CONTEXT
→ OLLAMA
→ FINAL RESPONSE

Identify the existing implementation first.

Do not rewrite the architecture.

---

# 2. Test the actual search tool independently

Find the web-search tool and execute it directly.

Test searches such as:

* `latest NVIDIA news`
* `latest AI news`
* `What is the current price of Bitcoin?`
* `Linux kernel latest release`
* `OpenAI latest news`

For each test record:

* whether the tool executed
* HTTP status
* response size
* number of results
* titles
* URLs
* snippets
* timestamp if available
* parsing success/failure
* timeout/error information

Do NOT use fabricated results for testing.

---

# 3. Verify the router

Determine how Lura decides that a request requires web search.

Test:

`What is the capital of France?`

This may not require live search.

Then test:

`What is the latest NVIDIA news?`

This SHOULD require web search.

Then:

`What is happening in AI today?`

This SHOULD require web search.

Then:

`Search the web for the latest Linux kernel release.`

This MUST explicitly trigger web search.

Verify that the router does not incorrectly classify current-information requests as ordinary knowledge questions.

---

# 4. Verify tool execution

For every request that requires web search, log:

* selected tool
* arguments
* search query
* tool start
* tool completion
* success/failure
* number of results
* execution time

Do not log secrets.

Make sure the model cannot claim:

"I searched the web..."

unless the tool actually returned success.

---

# 5. Use structured results

The web-search tool should return structured data similar to:

```json
{
  "success": true,
  "query": "latest NVIDIA news",
  "results": [
    {
      "title": "...",
      "url": "...",
      "snippet": "...",
      "source": "..."
    }
  ]
}
```

On failure:

```json
{
  "success": false,
  "error_code": "NETWORK_ERROR",
  "message": "Web search is currently unavailable."
}
```

Adapt this to the project's existing tool architecture rather than blindly copying this schema.

Do NOT pass uncontrolled raw HTML directly into the model.

---

# 6. Enforce accountability

Implement a hard rule:

### success=true + usable results

The model may say it searched the web and may use those results.

### success=false

The model MUST NOT claim that it searched successfully.

### zero results

The model MUST say that no usable results were found.

### timeout

The model MUST report that the search timed out.

### malformed response

The model MUST report that the search service returned invalid data.

Never silently convert a failed tool call into a normal answer.

---

# 7. Verify URLs and result integrity

Ensure every returned search result has a valid URL.

Do not invent URLs.

Preserve the actual title/snippet/source returned by the search provider.

If the provider returns duplicate results, deduplicate them safely.

---

Requests containing concepts such as:

* latest
* today
* current
* now
* recently
* this week
* breaking
* current price
* current version
