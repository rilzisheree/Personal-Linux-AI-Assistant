### 1. Multiple Wake Words / Wake Word Aliases

I want to be able to configure **multiple wake words** instead of having only one.

For example, I want to add:

```text
Luna
Luda
```

Because when I say "Luna", speech/wake-word detection sometimes interprets it as "Luda".

Both should trigger the exact same assistant behavior.

For example:

```text
"Luna, what's the weather?"
        ↓
Wake word detected
        ↓
Conversation starts
```

and:

```text
"Luda, what's the weather?"
        ↓
Wake word detected
        ↓
Conversation starts
```

### Requirements

* Allow multiple wake words/aliases in Settings.
* I should be able to add, remove, and edit wake words.
* Treat all configured wake words as equivalent.
* Detection of ANY configured wake word should activate the assistant.
* Do not require the user to say all wake words.
* Avoid duplicate triggers when multiple aliases are similar.
* Keep the existing wake-word detection system if possible.
* Make sure adding aliases doesn't significantly increase CPU usage or microphone processing.
* The configured wake words should persist after restarting the application.

Example configuration:

```text
Wake Words:
[x] Luna
[x] Luda
[+ Add wake word]
```

If the current wake-word engine only supports one phrase at a time, implement the cleanest reliable approach for supporting multiple aliases rather than creating several competing microphone streams.

**Quality + clarity + naturalness + low latency**

* Downsampling the generated audio
* Compressing it too aggressively
* Converting it through a low-quality format
* Reducing the sample rate
* Playing it through a poor-quality audio conversion step
