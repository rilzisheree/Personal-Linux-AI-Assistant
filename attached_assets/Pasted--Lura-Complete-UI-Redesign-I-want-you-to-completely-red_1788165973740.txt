# Lura — Complete UI Redesign

I want you to completely redesign the **existing Linux app UI from 0**.

## ⚠️ CRITICAL RULE

**THIS TASK IS DESIGN/UI ONLY.**

Do NOT modify, remove, rewrite, or break:

* Ollama integration
* AI/model logic
* tool calling
* terminal execution
* application control
* file tools
* voice processing/backend
* WebSocket/API logic
* database
* permissions
* existing functionality
* existing assistant behavior

You are redesigning the **visual experience and frontend only**.

If something needs to be changed to connect the new UI to an existing function, preserve the existing function and only adapt the UI to it.

Do not implement new backend functionality in this task.

---

# Design Direction

The app should feel like a **futuristic personal AI assistant**, inspired by a very clean sci-fi/JARVIS-style interface.

It should NOT look like a generic ChatGPT clone.

It should feel:

* premium
* futuristic
* minimal
* cinematic
* elegant
* mysterious
* extremely clean
* responsive
* alive

The interface should have **very few visible elements**.

The main focus of the application is the AI itself.

---

# Color System

The entire application should be approximately:

**90% black**
**10% very dark blue**

Primary background:

* near-black
* almost pure black

Secondary colors:

* extremely dark navy
* subtle dark blue
* blue glow

Avoid:

* bright blue UI everywhere
* gradients covering the entire screen
* colorful UI
* purple
* red
* green
* excessive borders
* excessive cards

Blue should mainly appear as a **subtle glow/accent**, not as the primary UI color.

The application should feel predominantly black.

---

# 1. Startup / Welcome Screen

When the application launches, do NOT immediately show the main interface.

Create a cinematic animated startup screen.

The screen should be almost entirely black.

Center the content.

Display:

**"Welcome, Sir."**

The text should appear with a smooth, elegant animation.

Possible animation:

```text
black screen
    ↓
subtle fade in
    ↓
"Welcome, Sir."
    ↓
slight glow
    ↓
smooth transition to password screen
```

The animation should be fast and polished.

Do not make it cheesy or overly dramatic.

Use smooth easing.

---

# 2. Password Screen

After the welcome animation, transition into a minimal password screen.

Keep the screen almost completely black.

Center:

```text
Enter Password
```

Then a minimal password input.

The input should NOT look like a generic HTML/login form.

Make it futuristic and minimal.

For example:

```text
              Enter Password

              • • • • • •
```

Use subtle animation when typing.

Pressing Enter should continue into the main application using the **existing authentication/password functionality**.

Do NOT change the authentication backend.

Only redesign its UI.

---

# 3. Main Interface

After authentication, the interface should become extremely minimal.

The main focus should be a single animated orb.

## AI Orb

Place a large orb in the center of the screen.

The orb should be approximately:

* black
* very dark blue
* subtle blue glow
* soft edges
* cinematic lighting

It should look like an **AI entity**, not a simple circle.

The orb should have subtle animated movement.

For example:

* slow breathing/pulsing
* subtle internal movement
* soft light shifting
* tiny changes in shape
* subtle blue energy around the edges
* very slow rotation-like movement

Keep the animation elegant.

Do NOT make it look like a flashy gaming RGB effect.

---

# 4. Orb States

The orb should visually react to what the assistant is doing.

Create different visual states.

## Idle

When nothing is happening:

```text
slow breathing animation
very subtle blue glow
minimal movement
```

The orb should feel alive but calm.

---

## Listening

When the user is holding the orb to speak:

```text
orb expands slightly
blue glow becomes stronger
animation becomes more responsive
```

The orb should clearly communicate:

**"I'm listening."**

---

## Thinking

When the AI is processing:

```text
internal movement increases
subtle waves/ripples
slightly stronger glow
```

Do not use a generic loading spinner.

The orb itself should communicate processing.

---

## Speaking

This is VERY important.

When the AI is talking, the orb should become significantly more animated.

The orb should react dynamically to the AI's speech.

Possible effects:

* pulsing
* expanding/contracting
* subtle waves
* glow intensity changing
* internal energy movement
* slight distortion
* responsive movement based on speech amplitude if available

The user should be able to immediately tell:

**"Lura is speaking."**

The animation should feel organic rather than like a visualizer with obvious bars.

---

# 5. Hold-to-Talk

REMOVE the traditional microphone button.

There should be **NO microphone button** in the main interface.

Instead:

## Hold the orb to talk.

Interaction:

```text
Mouse down on orb
        ↓
Listening begins
        ↓
Orb changes to listening state
        ↓
User speaks
        ↓
Mouse released
        ↓
Recording stops
        ↓
AI processes request
```

The orb itself is the microphone control.

Make this interaction feel natural.

The orb should visually react immediately when pressed.

---

# 6. Chat Interface

The chat should exist **under the orb**.

Do NOT use a traditional ChatGPT-style sidebar.

Do NOT make giant message cards.

Do NOT fill the screen with chat bubbles.

Instead, create a minimal conversation area underneath the orb.

Example:

```text
                 ◉
             AI ORB


       You
       Open Firefox.


       Lura
       Opening Firefox.


       You
       What's my GPU usage?
```

Keep the messages subtle.

User messages and AI messages should be visually distinguishable without huge colored bubbles.

Use:

* small typography
* lots of spacing
* subtle opacity
* smooth appearance animations

The conversation should feel like part of the assistant rather than a separate chat application.

---

# 7. Text Input

Keep a text input available for users who don't want to use voice.

Place it near the bottom.

It should be extremely minimal.

Something similar to:

```text
        Ask Lura anything...
```

No huge rectangular input box.

Use a subtle dark surface or barely visible border.

Press Enter to send.

---

# 8. Wake Word System UI

Add a new setting:

## Wake Word

Default:

**Lura**

The user must be able to change it.

Examples:

```text
Wake Word

● Enabled

Wake word:
[Lura]
```

The setting should allow:

* enable/disable wake word
* change wake word

Do NOT hard-code the UI to only display Lura.

The backend implementation should remain untouched in this design task.

If wake-word functionality already exists, connect the new setting to the existing functionality.

If it doesn't exist yet, ONLY create the UI/settings design for it.

Do not implement the backend in this task.

---

# 9. Wake Word Behavior UI

The intended experience is:

```text
Assistant idle
        ↓
Listening for wake word
        ↓
"Lura"
        ↓
Assistant wakes
        ↓
User can speak
        ↓
15-second active listening period
        ↓
No more speech
        ↓
Return to wake-word listening
```

The assistant should NOT require the user to say "Lura" before every single sentence.

After waking up, it should remain active for approximately **15 seconds**.

During this 15-second period, the UI should clearly show that the assistant is actively listening.

The orb should reflect this state.

After the period expires, return to the normal idle/wake-word state.

Again:

**Do not implement backend changes during this redesign.**

Only make sure the UI has appropriate states for this behavior.

---

# 10. Wake Word Visual State

When wake-word mode is active, show a very subtle indication somewhere in the interface.

For example:

```text
Listening for "Lura"
```

But keep it extremely subtle.

Do NOT put a giant "LISTENING" label on screen.

The orb itself should communicate most of the state.
