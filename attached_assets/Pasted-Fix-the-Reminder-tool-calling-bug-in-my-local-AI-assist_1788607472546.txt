Fix the **Reminder tool-calling bug** in my local AI assistant **Lura**.

## CURRENT BUG

When I ask Lura to create a reminder, for example:

```text
Remind me in 5 minutes to check my downloads.
```

or:

```text
Set a reminder for 3:00 PM to do my homework.
```

Lura fails with:

```text
Ollama returned an error:
The model requested a tool although no tools were enabled.
```

This indicates that the model is attempting to call a reminder tool, but the Ollama generation request was sent without the corresponding tool definitions enabled.

## GOAL

Make reminder creation work reliably again.

The intended flow is:

```text
USER
↓
ROUTER / TOOL SELECTION
↓
REMINDER TOOL AVAILABLE
↓
OLLAMA RECEIVES REMINDER TOOL SCHEMA
↓
MODEL REQUESTS REMINDER TOOL
↓
REMINDER TOOL EXECUTES
↓
STRUCTURED TOOL RESULT
↓
MODEL GENERATES FINAL RESPONSE
```

## INVESTIGATE BEFORE MODIFYING

Inspect the complete tool-calling path:

```text
user request
→ router/classifier
→ selected tools
→ tool registry
→ tool schema generation
→ Ollama request construction
→ Ollama tools parameter
→ model tool call
→ tool dispatcher
→ reminder implementation
→ final response
```

Find exactly where the reminder tool is being lost.

Specifically inspect:

* reminder tool registration
* tool registry
* tool names
* tool schemas
* tool availability
* router output
* selected-tool list
* Ollama request construction
* `tools` parameter passed to Ollama
* whether tools are only enabled for certain request paths
* whether the reminder path accidentally sends `tools=[]` or `tools=None`
* whether a second model request after routing loses the tools
* whether tool definitions disappear after conversation/history construction
* whether the model is using an old/incorrect reminder tool name

## IMPORTANT

Do NOT simply disable tool calling.

Do NOT make reminders work by having the model pretend that it created one.

Do NOT hardcode a fake reminder response.

The reminder must actually be created by the reminder system.

If the tool call fails, Lura must honestly report the failure.

## VERIFY THE TOOL SCHEMA

Find the actual reminder tool definition and verify that it is valid for the Ollama tool-calling format.

Verify:

```text
tool name
description
parameters
required parameters
parameter types
JSON schema
```

Make sure the tool definition actually reaches the Ollama request when a reminder request is processed.

For example, the request should conceptually contain:

```text
tools: [
    {
        type: "function",
        function: {
            name: "...reminder tool...",
            description: "...",
            parameters: {...}
        }
    }
]
```

Use the project's existing schema and naming conventions rather than inventing a new interface.

## MULTI-TURN TOOL FLOW

For example:

```text

↓

↓

↓
```

Do not accidentally do:

```text

```

