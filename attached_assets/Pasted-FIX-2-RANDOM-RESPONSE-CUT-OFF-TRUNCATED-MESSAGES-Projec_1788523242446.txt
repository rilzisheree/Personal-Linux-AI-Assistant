FIX #2 — RANDOM RESPONSE CUT-OFF / TRUNCATED MESSAGES

Project:

~/Personal-Linux-AI-Assistant

This is now the highest-priority bug.

Lura frequently starts generating a response and then abruptly stops in the middle of a sentence.

Examples:

latest NVIDIA news...

stops halfway.

latest AI news...

stops halfway.

Elden Ring information...

stops halfway.

Cyberpunk 2077...

stops halfway.

full system status...

stops halfway.

Reminder creation responses can also be cut off.

This appears to be an actual pipeline/streaming problem, not merely the model choosing a short answer.

IMPORTANT

Do NOT rewrite the application.

Do NOT increase token limits blindly and declare the issue fixed.

Do NOT simply catch an exception and return whatever text was generated.

Do NOT hide errors.

Inspect the existing implementation first and determine the exact cause.

TRACE THE ENTIRE RESPONSE PIPELINE

Inspect and trace:

USER REQUEST
↓
ROUTER
↓
TOOL EXECUTION (if applicable)
↓
OLLAMA REQUEST
↓
OLLAMA STREAM
↓
BACKEND STREAM PROCESSOR
↓
SSE / HTTP STREAM
↓
FRONTEND STREAM HANDLER
↓
MESSAGE STATE
↓
FINAL DISPLAYED RESPONSE

Determine where the response is actually being truncated.

I want you to investigate ALL plausible termination points.

1. OLLAMA STREAMING

Inspect the Ollama integration.

Check:

streaming configuration

Determine whether Ollama itself is terminating generation or whether Lura is terminating the stream prematurely.

Do not change generation parameters unless you have evidence they are responsible.

2. BACKEND STREAMING

NORMAL_COMPLETION

STREAM_ERROR

USER_CANCELLED

Inspect the API endpoint that sends streamed responses to the frontend.

Check:

chunk 2
chunk 3

chunk 5

4. FRONTEND STREAM HANDLING

Inspect the frontend code that consumes the stream.

Check whether it:

stops reading after one event
incorrectly detects [DONE]
treats an empty chunk as completion
has race conditions with state updates
overwrites accumulated text
aborts the request accidentally
has a timeout
cancels requests during rendering
loses chunks because of React/state update behavior
closes the connection prematurely

The frontend must accumulate the entire response.

Conceptually:

incoming chunk
↓
append to existing response
↓
continue reading
↓
repeat
↓
final completion event
↓
finish message

It must NOT behave like:

↓

↓
finish
5. STOP SEQUENCES

Inspect all configured stop sequences.

Pay particular attention to:

Do not remove tool-call stopping behavior blindly.

If stop sequences are causing normal conversational responses to terminate, fix them at the correct layer.

6. XML INTERACTION

For this task, investigate whether XML parsing is causing the response truncation.

For example:

→ parser assumes tool call

If this is happening, identify it clearly.

Do NOT perform a broad XML rewrite unless it is required to fix the streaming bug.

7. TOKEN LIMITS

Inspect the actual Ollama generation configuration.

Determine:

context window
num_predict
max output tokens
any application-level maximum response length
frontend maximum text length
API response limits

If the model is genuinely reaching its configured output-token limit, identify that as the cause.

However, distinguish between:

MODEL REACHED TOKEN LIMIT

and:

STREAM WAS PREMATURELY TERMINATED

These are different bugs.

Do not simply increase the token limit without determining which one is occurring.
