### BUG 3 — OLLAMA TIMEOUT

When I send a message through chat, I get:

**"Ollama unavailable: timed out. Check the service and the URL in Settings."**

This needs to be investigated immediately.

Do NOT assume Ollama itself is broken.

Inspect how the application connects to Ollama.

Check:

* Ollama URL from Settings
* Ollama host/port
* Whether the application can actually reach the configured URL
* Whether Ollama is running
* Whether the selected model exists
* Whether the model is currently loaded
* Request timeout configuration
* Whether the timeout is unrealistically short
* Whether the application is waiting for the entire response instead of streaming
* Whether the request is being sent to the wrong endpoint
* Whether the frontend/backend architecture is preventing the request from reaching Ollama
* Whether CORS/network configuration is involved
* Whether the application is accidentally trying to connect to a remote Ollama instance instead of the local one

If this is supposed to be local Ollama, verify the actual local Ollama service before changing application code.

The application should provide a useful distinction between:

```text
Ollama not running
Ollama URL unreachable
Model doesn't exist
Request timed out
Model is loading
Generation is slow
```

Do not incorrectly label all of these as "Ollama unavailable."

### IMPORTANT — Don't hide slow generation with a timeout

If Ollama is reachable but the model simply takes time to load or generate its first token, don't immediately classify that as a connection failure.

Measure:

```text
Request sent
↓
Connection established
↓
Model loading
↓
First token
↓
Generation
```

A model taking a while to produce its first token is different from Ollama being unreachable.

Use streaming responses where appropriate.
