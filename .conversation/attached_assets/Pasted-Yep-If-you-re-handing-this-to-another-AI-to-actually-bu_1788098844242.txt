Personal AI Assistant — Linux App First

Project Goal

Build a personal AI assistant application for my Linux PC.

The first version should be a native Linux desktop application that provides a ChatGPT/Jarvis-style interface and connects to my local Ollama installation.

The application should eventually be capable of understanding text and voice, executing approved actions on the Linux desktop, and later being controlled remotely from my phone through a web app.

Important: Do NOT build the phone/web application yet. Only design the architecture so it can be added later without rewriting the Linux application.

⸻

1. Current Environment

OS:

* CachyOS
* Hyprland
* Linux
* NVIDIA RTX 4060
* Intel i5-12400F

AI runtime:

* Ollama

Currently installed Ollama models:

* qwen3.5:4b
* qwen3.5:2b
* llama3.1:8b-instruct-q4_K_M
* qwen3:8b

Current preferred model:

ollama/qwen3.5:4b

The application should allow the model to be changed later through settings.

⸻

2. Linux Application

Build the Linux application first.

Recommended stack:

Backend

* Python 3
* FastAPI or a lightweight internal Python service
* Ollama API
* WebSocket support
* SQLite for local data

GUI

Use:

* PySide6
* Qt

The GUI should feel like a modern AI assistant rather than a traditional Linux utility.

Do NOT build a web-based GUI for the Linux application unless there is a strong technical reason.

⸻

Use a modular architecture.

Linux AI Assistant
│
├── GUI
│   └── PySide6 / Qt
│
├── Assistant Core
│   ├── conversation manager
│   ├── model manager
│   ├── tool manager

    └── WebSocket / HTTP

Keep each component separate.

4. AI Communication

The application should communicate directly with Ollama.

Do NOT use OpenClaw.

Do NOT use Telegram.

Do NOT depend on a cloud AI provider.

The application should send requests to the local Ollama API.

Example:

User
 ↓
Linux GUI
 ↓
Assistant Core
 ↓
Ollama
 ↓
Qwen 3.5

The Ollama model should be configurable.

Default:

qwen3.5:4b

⸻

5. Tool Calling

This is one of the most important parts.

The AI must be able to call actual application tools.

Do NOT simply ask the model to output fake JSON and then display that JSON to the user.

The application should implement a real tool/function-calling layer.

Example:

User:

Open Firefox

Assistant:

AI determines that the open_app tool is required.

Application executes:

open_app("firefox")

Firefox launches.

Assistant responds:

Done.

The user should never need to manually copy commands.

⸻

6. Initial Tools

Implement these tools first.

Application control

open_app(app)
close_app(app)
restart_app(app)

Example:

open_app("firefox")

⸻

Terminal

Provide:

exec(command)

However, this MUST have a permission/safety layer.

Commands that can modify/delete large amounts of data should require confirmation.

For example:

rm -rf
mkfs
dd
shutdown
reboot
sudo

should not automatically execute without confirmation.

⸻

8. Window Management

Because I use Hyprland, support Hyprland where possible.

Implement tools such as:

Use Hyprland’s native tools/IPC where appropriate.

Do not assume GNOME/KDE behavior.

Add a screenshot tool:

The assistant should eventually be able to inspect the screenshot with a vision-capable model.

The architecture should support models with image input.

The current qwen3.5:4b installation supports image input, so keep the system compatible with that.

Example:

User:

Assistant:

1. Take screenshot

4. Respond

19. Permissions / Security

The assistant has the ability to control the computer, so security is important.

Create a permission system.

Tools should have categories:

SAFE
CONFIRMATION_REQUIRED
DANGEROUS

Example:

SAFE:

get_cpu_usage
get_ram_usage
open_app
list_windows

CONFIRMATION_REQUIRED:

write_file
move_file
close_app
exec

DANGEROUS:

delete_file
rm
sudo commands
disk operations
shutdown
reboot

Never allow the AI to bypass the permission system.

The model decides WHAT it wants to do.

The application decides WHETHER it is allowed to do it.

23. Important Development Rules

Do NOT:

* use OpenClaw
* use Telegram
* require cloud AI
* hard-code a single Ollama model
* put all code into one giant Python file
* allow unrestricted shell execution
* fake tool calls by parsing arbitrary assistant text
* build the phone application yet

Do:

* keep the project modular
* use local Ollama
* use real tool functions
* implement permissions
* support streaming responses
* handle errors cleanly
* keep secrets/configuration outside source code
* design the API so a web client can be added later
* prioritize reliability over adding hundreds of features
